k3sm

Install

Download for Mac

The k3sm app, for Apple silicon and macOS 26 or newer, Developer ID signed and notarized by Apple.

Or from the terminal, in one line. Apple silicon, macOS 26 or newer.

curl -fsSL https://k3sm.io/install.sh | sh

To look first, download and verify without installing:

curl -fsSL https://k3sm.io/install.sh | K3SM_INSTALL_DOWNLOAD_ONLY=1 sh

That downloads and SHA-256-verifies the tarball into the current directory and never invokes sudo. Inspect it, then tar -xzf and run sudo ./k3sm install yourself.

To install a specific release, pin it:

curl -fsSL https://k3sm.io/install.sh | K3SM_INSTALL_VERSION=v0.2.2 sh

Status: every program in the release tarball is Developer ID signed and notarized by Apple. The script resolves the newest release, and a pin via K3SM_INSTALL_VERSION always wins. The releases page lists every version you can pin.

What the script does

  1. Preflight. Verifies Apple silicon (even from a Rosetta shell) and macOS 26+. Anything else stops before a byte is downloaded.
  2. Fetch. Downloads the versioned release tarball and its checksums file from github.com/k3sm-io/k3sm Releases.
  3. Verify. Checks the tarball’s SHA-256 against the published checksums entry. Any mismatch, or a missing entry, aborts before anything runs.
  4. Tell you exactly what happens next. Prints the resolved version, the tarball’s SHA-256, and what the install step will do, before any privilege is requested.
  5. sudo k3sm install. The one-time admin step: creates the root-owned /Library/k3sm, the unprivileged _k3sm service user, the io.k3sm.netd (root) and io.k3sm.server (_k3sm) LaunchDaemons, and writes an admin kubeconfig to your home directory. Day-to-day use needs no sudo afterwards.

This script escalates. Step 5 runs under sudo and will prompt for your password (unless your sudo credentials are already cached; the banner in step 4 prints either way). If you would rather look first, use the download-only form at the top of this page.

You can also read the script itself. Its SHA-256 as served here is:

97d573656c23a771b1cfcc2f53e10df8109e299abc22381a728dbfa0edd940f5

and the canonical copy lives at github.com/k3sm-io/k3sm/install.sh, same bytes from a different origin, so the two can be compared out-of-band.

Verification scope: the SHA-256 check confirms integrity (the tarball matches its published checksums), not publisher identity. Identity comes from the Developer ID signature on each program in the tarball, which codesign -dvv prints (verifying a download).

Upgrades, repair, rollback

  • Upgrade: re-run the one-liner. Both LaunchDaemons restart briefly; cluster state is preserved.
  • Repair without upgrading: an unpinned re-run jumps to latest, so pin the version you are on with the pinned form at the top of this page.
  • Rollback: pin the prior release tag and re-run.
  • Remove: sudo k3sm uninstall removes everything the install created (it is idempotent, and safe after a failed or partial install).

The two channels

  1. curl -fsSL https://k3sm.io/install.sh | sh: a checksum-verified tarball, handed to the first-class sudo k3sm install.
  2. The k3sm app, a signed and notarized download from k3sm.io.

Switching channels (from one channel to another) is safe: every channel manages the same /Library/k3sm. Run sudo k3sm install after switching so the daemons run the newly delivered binary, or run sudo k3sm uninstall first for a clean cutover.
