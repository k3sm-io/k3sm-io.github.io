k3sm

Install

One line. Apple silicon, macOS 26 or newer.

curl -fsSL https://k3sm.io/install.sh | sh

Status: no k3sm release is published yet. Until the first tagged release exists, the script stops cleanly with a “has a release been published yet?” message and installs nothing.

What the script does

  1. Preflight. Verifies Apple silicon (truthful under Rosetta) and macOS 26+ — anything else stops before a byte is downloaded.
  2. Fetch. Downloads the versioned release tarball and its checksums file from github.com/k3sm-io/k3sm Releases.
  3. Verify. Checks the tarball’s SHA-256 against the published checksums entry. Any mismatch — or a missing entry — aborts before anything runs.
  4. Tell you exactly what happens next. Prints the resolved version, the tarball’s SHA-256, and what the install step will do — before any privilege is requested.
  5. sudo k3sm install. The one-time admin step: creates the root-owned /Library/k3sm, the unprivileged _k3sm service user, the io.k3sm.netd (root) and io.k3sm.server (_k3sm) LaunchDaemons, and writes an admin kubeconfig to your home directory. Day-to-day use needs no sudo afterwards.

This script escalates. Step 5 runs under sudo and will prompt for your password (unless your sudo credentials are already cached — the banner in step 4 prints either way). If you would rather look first, verify without installing:

curl -fsSL https://k3sm.io/install.sh | K3SM_INSTALL_DOWNLOAD_ONLY=1 sh

That downloads and SHA-256-verifies the tarball into the current directory and never invokes sudo. Inspect it, then tar -xzf and run sudo ./k3sm install yourself. You can also read the script itself — its SHA-256 as served here is:

8e54258e741e9d4874fb1aa286862704e538febd055c0dd7a3aaa14f933402e3

and the canonical copy lives at github.com/k3sm-io/k3sm/install.sh — same bytes, different origin, so the two can be compared out-of-band.

Verification scope: the SHA-256 check proves integrity — the tarball matches its published checksums — not publisher identity. Identity (Developer ID + notarization) arrives with the .pkg generation below.

Upgrades, repair, rollback

  • Upgrade: re-run the one-liner. Both LaunchDaemons restart briefly; cluster state is preserved.
  • Repair without upgrading: an unpinned re-run jumps to latest — pin the version you are on: K3SM_INSTALL_VERSION=v0.1.0 sh.
  • Rollback: pin the prior release tag and re-run.
  • Remove: sudo k3sm uninstall — removes everything the install created (it is idempotent, and safe after a failed or partial install).

The three generations

This installer is generation 1 of k3sm’s distribution ladder, and it ships first:

  1. curl -fsSL https://k3sm.io/install.sh | sh — checksum-verified tarball, handed to the first-class sudo k3sm install.
  2. brew install k3sm-io/tap/k3sm — the Homebrew tap.
  3. A signed, notarized, stapled .pkg — full publisher provenance, for offline and managed installs.

Switching channels (script → brew or back) is safe: every channel manages the same /Library/k3sm. Run sudo k3sm install after switching so the daemons run the newly delivered binary — or sudo k3sm uninstall first for a clean cutover.
