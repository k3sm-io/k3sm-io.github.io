Community

Where to ask questions, how to contribute, and how the project is governed. GitHub Discussions is the front door.

k3sm is an early, small project with a discussions board, an issue tracker, and an email address; all three are read.

Start with Discussions#

GitHub Discussions is the front door. Questions, “is this the right tool for what I am doing”, design arguments, and half-formed ideas all belong there. Answering a question in the open is worth more than answering it privately, so please prefer it to email.

Use the issue tracker when you have a specific reproducible bug or a concrete change to propose. Issues live in the repository the problem is in:

repositoryfile an issue here when
k3smthe CLI, install, the control plane, the node, packaging — and anything you are not sure how to place
runtimedPod execution, the Seatbelt sandbox, images, resource limits
darwin-netPod IPs, Services, DNS, the multi-Mac mesh
apisthe shared gRPC, CRD, and Go contracts

Security problems do not go in any of those. See security.

Before You Open Anything#

Two pages save everyone time. limitations lists the behaviors that diverge by design: restartPolicy, CPU limits, NetworkPolicy, volume mounts inside a shell, which addresses a Service answers on, so you can tell a bug from a documented trade. troubleshooting covers the failures that come up most often during bring-up.

If a documented trade seems wrong to you, open a discussion. If a documented limitation surprised you, open an issue saying the page did not warn you clearly enough.

Contributing#

Contributions are welcome, and the requirements are written down.

  • CONTRIBUTING — how to build, the commit-message format, and what a reviewable pull request looks like.
  • Every commit needs a Developer Certificate of Origin sign-off (git commit -s). This is enforced: an unsigned commit does not merge.
  • The Go conventions every repository shares are checked in, identical across all four, and linked from CONTRIBUTING. Formatting, vet, and tests are the commit gate.
  • Docs count. A correction to a page that was wrong, unclear, or too generous about what k3sm does is as valuable as code here.

Good first contributions: reproduce a documented limitation on your own hardware and say what you saw; improve a troubleshooting entry; port a real workload and write up where it broke.

Governance and Conduct#

  • GOVERNANCE: roles, decision-making, and how maintainers are added. It describes a maintainer-council model the project is growing into; the thresholds become meaningful as the council grows.
  • MAINTAINERS: currently a single founding maintainer, @kitsumiko.
  • Code of Conduct — governs all participation, in every repository and every discussion. Report a violation to kitsumiko@k3sm.io.

Contact#

  • General contact: kitsumiko@k3sm.io.
  • Maintainer — @kitsumiko on GitHub.
  • Security reports — not by email first; follow security.
